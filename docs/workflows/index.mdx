# Output pipelines

This section documents generation code paths, not user journeys, setup tasks, scheduling,
analytics, authentication, or account management.

A pipeline is an ordered sequence of transformations. Each stage accepts an input and emits an
output. `...output` means the entire preceding stage output is piped into the next stage.

## Pipelines in the application

| Pipeline | Initial input | Final output | Availability |
| --- | --- | --- | --- |
| [Slideshow generation](/docs/workflows/slideshow-generation) | Automation schema, hooks, collections, and generation context | Rendered slideshow images and optional MP4 | Shipped |
| [X and Threads generation](/docs/workflows/x-threads-generation) | Persisted social automation, niche brief, optional topic/trend | Validated X post/thread or Threads post | Shipped |
| [LinkedIn generation](/docs/workflows/linkedin-generation) | Niche, persona, proof, optional brief, and model selection | One to four validated LinkedIn posts | Generation endpoint shipped; persistence/scheduling are not wired |
| [UGC video generation](/docs/workflows/ugc-video-generation) | Product source, actor, voice, duration, and media settings | Talking-actor MP4 and thumbnail | Implemented; gated by `ENABLE_UGC_AUTOMATION=true` |

## Documentation contract

Every pipeline page contains only:

1. the initial input contract;
2. ordered processing stages;
3. valid JSON input and valid JSON output for every stage;
4. the exact model and API provider for generative stages;
5. branches, validation, retries, persistence, and the final output contract.

Supporting processes such as authentication, collection management, notification delivery,
account connection, scheduling, analytics import, and analytics reporting are documented outside
this section because they do not generate a content output.
