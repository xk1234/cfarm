LumenClip is a content-production and automation workspace. It turns reusable
media collections, templates, and automation definitions into finished social
content: slideshow images with an optional MP4, X and Threads posts, LinkedIn
posts, and AI UGC video. Generated output is reviewed in the workspace, planned
on a shared content calendar, published through PostFast, and tracked with
imported analytics.

This documentation covers the code that produces that content and the
structures it is stored in, across five areas maintained alongside the
application.

## Start here

- **Add or change a generation workflow.** Read the documentation contract in
  [Output generation](/docs/workflows), then the pipeline page closest to what
  you are building.
- **Change which model a stage uses.** Check the model summary in
  [Output generation](/docs/workflows) for the model and provider at every
  generative stage, and [AI models](/docs/ui/settings/ai-models) for the model
  IDs an operator can set from the workspace.
- **Debug a failed run.** Start with [Backend scheduling](/docs/jobs/backend)
  for job states, retry backoff, dead-letter handling, and the triage table.
- **Understand a persisted shape.** Open the [Data dictionary](/docs/data) and
  the domain group that holds the object you are changing.
- **Find an API route.** Search the route-handler inventory in
  [Backend endpoints](/docs/data/backend-endpoints).
- **Decide where a dependency belongs.** Check
  [Libraries and dependencies](/docs/libraries) before adding a package.

## Documentation rules

- Keep only content-output generation workflows in `docs/workflows/`. Express
  each pipeline as ordered transformations with explicit inputs, outputs,
  branches, validation, and model/provider details.
- Keep dependency ownership in `docs/libraries/`.
- Keep persisted shapes and backend contracts in `docs/data/`.
- Keep frontend architecture and product surfaces in `docs/ui/`.
- Keep scheduled execution behavior in `docs/jobs/`.
- Update the relevant document with every material implementation change.
